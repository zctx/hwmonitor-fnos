## 主要修复

- 首次远程下载不再使用 modinfo 无法识别的 `.ko.tmp` 后缀。
- 内置模块与缓存每次加载都校验 SHA256、大小、ELF、模块元信息，禁用远程后不读取旧远程缓存。
- root 专用缓存目录及符号链接、所有权、写权限检查。
- 异步网络和 kmod 子进程，HTTPS 跳转限制、长度上限、总超时、停止取消及单任务重试。
- 只有模块身份与 hwmon/PWM 节点完整才标记加载成功；延迟加载后执行现有 BIOS 模式对齐。
- 独立 `kernel-modules-v2` 通道，补齐缺失中间内核；严格维护旧索引，模块先发布、索引最后更新，拒绝覆盖已发布模块。
- 构建、发布作业权限分离，headers 必须校验，完整源码提供对应驱动 C 源码。

驱动 0.2.0 C 源码、既有温控算法、曲线和 UI 不变；旧 1.5.6 / 1.5.7 Release 附件不覆盖。

## 已完成验证

31 个 Node 测试及 30 个 Python 测试全部通过，没有跳过。含真实 `.ko` 的 modinfo 回归和最终 FPK 反向解包验证。构建日志在附件中。

未在用户 NAS 上执行真实 insmod 或 PWM 控制。N5A/F8NAB 在上游仍是 experimental write profile；安装后观察 RPM 和温度，再考虑转发给其他用户。

## 自动适配边界

v2 通道只接受 `6.18.18.cNNNN-trim`，依赖匹配 headers、固定驱动兼容性、GitHub 网络和 CI 可用，不是永久免维护。SHA256 不是独立签名，当前信任指定 GitHub 仓库的 HTTPS 发布权限。找不到合适模块时不强制加载相近内核的模块。

详细审查、遗留项与信任边界见仓库 `docs/REVIEW-1.5.7.md`。
