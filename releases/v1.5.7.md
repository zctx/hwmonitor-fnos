# hwmonitor-fnos v1.5.7

面向 Minisforum N5A / F8NAB 的 fnOS 内核升级适配。本版新增 `6.18.18.c1126-trim`，并引入“精确内核模块自动通道”，减少以后 fnOS 仅变更内核 build 号时反复重新安装 FPK 的需求。

## 适配对象

- 机器：Minisforum N5A / N5 Air
- DMI：`product_name=N5A|N5 AIR`、`board_name=F8NAB`
- 内置内核模块：
  - `6.18.18.c1032-trim`
  - `6.18.18.c1126-trim`
- hwmonitor upstream：`ltdstudio/hwmonitor v1.5.1`
- N5 driver upstream：`ltdstudio/minisforum-n5-it5571 0.2.0`

## 一劳永逸机制

1. 应用始终优先使用 FPK 内与 `uname -r` 完全匹配的模块。
2. 如果未来 fnOS 升级到新的 `6.18.18.cNNNN-trim`，且 FPK 内没有对应模块，应用查询本仓库的滚动 `kernel-modules` Release。
3. GitHub Actions 每天检查新的 fnOS x86 c-kernel 构建环境，并为新内核编译精确 `.ko`。
4. 应用只接受与当前内核完全匹配的条目；下载后依次校验 SHA256、vermagic、driver version、srcversion 和所需模块参数。
5. 校验通过后缓存并热加载；若模块尚未发布或网络不可用，每 5 分钟重试。
6. 找不到正确模块时不会强制加载旧模块，BIOS/EC 保持默认风扇控制。

这不是绕过 Linux 内核模块 ABI 检查，而是自动生产并分发“每个内核自己的模块”。若 fnOS 更换大版本内核、驱动接口发生不兼容变化或上游驱动版本改变，自动通道会失败关闭，需要新版本人工确认。

## 1.5.6 功能全部保留

- 多 NVMe 按 sysfs device 路径精确绑定。
- NVMe 风扇控制使用该盘最高传感器温度。
- 重名 hwmon 温度源使用唯一 ID。
- SPD5118 归类 memory。
- N5 EC CPU Temp / board 温度分组修正。
- HDD/SATA cached/stale 标记。
- SSD/HDD 软件曲线最低 PWM 为 `77/255`。
- UI 显示真实自动温度源。

## 安全提示

N5A/F8NAB 在上游 0.2.0 驱动中仍属于 experimental PWM write profile。本包仍只在精确 DMI 匹配时使用上游预留的 `experimental_write=1`。首次使用手动/曲线控制时请确认风扇 RPM 与温度响应正确。

## 关闭自动驱动通道

如不希望应用联网获取未来内核模块，可在运行环境设置：

```text
HWMON_N5_REMOTE_DRIVER=0
```

此时仅使用 FPK 内置模块。
