# 1.5.7 变更审查与 1.5.8 修正

审查基线：adapter `cb2e767219980ce14585aad1e31ea9b568a39c43`；已发布 FPK SHA256 `79acc3e12cb2c7b5c028a8883047c2b25ef3d3685e0067d1e473537e22033bc4`。

## 结论

1.5.7 的 c1032/c1126 内置模块构建确实成功，但远程驱动的首次加载路径没有完成行为验证，不能称为“自动适配已完整跑通”。本次保留驱动 0.2.0 C 源码及已有温控/曲线算法，只修正加载、缓存与构建发布链。

## 发现与修复

| 级别 | 问题与触发条件 | 1.5.8 处理 |
|---|---|---|
| P1 | 首次远程下载保存为 `.ko.tmp`，`modinfo` 按模块名而非合法模块文件处理，报 Module not found。已使用真实发布模块复现。 | 随机临时文件，最终扩展名始终 `.ko`；通过校验才原子放入缓存。 |
| P1 | `availableBuilds()` 直接扫描缓存文件名，缓存命中跳过 SHA256/modinfo；关闭远程开关后仍会加载缓存。 | 随包策略与每内核回执；每次加载都验证大小、SHA256、ELF、modinfo；开关关闭时只允许内置模块。 |
| P1 | 环境变量缺失时，root 进程回退到可预测 `/tmp/hwmon-data` 使用代码缓存；未检查父目录、符号链接和写权限。 | 独立 `/var/cache/hwmonitor-fnos/n5`；root 所有、不可由组/其他用户写入、目录不允许符号链接；文件 `O_NOFOLLOW`/独占创建。 |
| P1 | `execFileSync` 网络下载阻塞服务事件循环，同一进程内的温控、告警和停机处理随之延迟。 | HTTPS 与 kmod 子进程异步；下载跨重定向总超时、长度上限；单次任务串行重试，停止服务时取消。 |
| P1 | 模块出现在 `/sys/module` 就当作成功，没有确认 probe/hwmon/PWM；延迟加载成功后没有做启动模式对齐。 | 检查已加载身份、N5A 参数与完整节点；不抢占别的模块；自己加载后 probe 不完整则尝试卸载；延迟加载后执行已有 BIOS 模式对齐。 |
| P2 | 下载允许 HTTP 降级/任意主机重定向，没有长度上限和完整响应检查。 | 固定 GitHub HTTPS 主机范围、限制重定向次数、字节数与总时长，拒绝中断和长度不一致的响应。 |
| P2 | CI 只构建最新内核，跳过中间内核；读取旧索引失败时 `|| true` 可能以空索引重新发布。 | 计划构建元数据中 c1032 起同系列的全部缺失内核；只有明确不存在的新通道能初始化；网络/格式/附件异常直接中止，不抹掉旧记录。 |
| P2 | 浮动 metadata、可选 headers 校验、构建与发布共用写权限、并发发布可能丢索引。 | 构建时锁定 metadata commit；强制 SHA256 与官方域名/准确包名/架构校验；只读构建与写入发布作业分离；通道发布串行，模块先发布、索引最后替换。 |
| P2 | 发布源码归档没有包含对应驱动 C 源码。 | 完整工程归档及驱动通道一并提供锁定 commit 的驱动源码归档；保留上游许可说明。 |

## 验证方式

- Node.js：31 个加载/缓存/网络/生命周期测试，包括缓存篡改、首次远程加载、HTTP 降级、截断响应、超时、取消、并发加载与 probe 失败。
- Python：30 个构建与索引测试，包括必需 SHA256、精确内核包、错误主机、索引不丢旧条目、拒绝覆盖既有内核、全部缺失内核计划及文件身份。
- 使用真实 c1126 `.ko` 调用真实 `modinfo`，复现旧 `.ko.tmp` 失败；所有测试均不向测试机执行真实 `insmod` 或 PWM 写入。
- FPK 反向解包检查：manifest、app.tgz MD5、应用版本、内置模块 SHA256/元信息、策略及 JavaScript 语法。
- `app/web/app.js` 与 1.5.7 字节一致。1.5.6 温度映射与曲线补丁保留，存储软件曲线下限仍为 77/255。

CI 构建通过不等于 N5A 新内核实机验收。仍需要安装后检查实际内核版本、驱动、风扇 RPM 和温度变化。

## 兼容与信任边界

- 1.5.8 使用独立 `kernel-modules-v2` 通道；不修改 1.5.6/1.5.7 FPK，也不继续向存在上述漏洞的旧客户端分发新模块。旧 `kernel-modules` 保持已发布内容。
- 首次安装内置 c1032/c1126。其他 `6.18.18.cNNNN-trim` 取决于可取得的精确 headers、驱动编译成功及通道可用；新的基础内核版本不会被自动猜测兼容。
- SHA256 与 `srcversion` 不是安全签名。本方案信任随 FPK 安装的代码、固定 GitHub 仓库的 HTTPS 通道及仓库维护权限；不能防御仓库账号/发布权限被攻破。没有宣称独立签名认证。
- GitHub 同名资产替换不是原子事务。索引最后替换，失败尽力恢复旧索引；客户端仍可能短暂遇到 404，届时保留有效缓存或稍后重试，不强行加载。
- 内核源码与头文件内容及部分工具包仍是供应链输入；镜像和构建元数据已锁定，不能据此宣称所有产物逐位可复现。
- N5A PWM 写入仍是上游 experimental profile。77/255 是软件输出下限，不是所有风扇必定转动的物理保证。缺少正确驱动时不强制加载；正常冷启动依赖 BIOS/EC 默认控制，不代表任意故障下都有硬件兜底。
- 遗留项未扩展修改：重复芯片 source ID 中的 `hwmonX` 不是跨重启稳定硬件标识；手动绑定此类温度源的用户重启后应复核。HDD 缓存年龄和物理传感器位置也不能仅凭旧巡检脚本的“通过”确认。
